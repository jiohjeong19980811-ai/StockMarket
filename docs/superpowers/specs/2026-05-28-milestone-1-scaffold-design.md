# Milestone 1 Scaffold Design

Last updated: 2026-05-28T15:04:02-04:00

## Goal

Create the first application scaffold for StockMarket without weakening the research-first, paper-trading-first safety boundary. The scaffold should establish a TypeScript monorepo, validation commands, environment validation, and package boundaries for later domain, data, scoring, backtesting, paper-trading, API, and UI work.

## Context

Milestone 0 is complete and committed on `feature/codex-foundation-setup` in commit `7528583`. The foundation now includes Codex hooks, project guidance, external research, quant strategy research, risk/compliance docs, and lightweight status tracking.

The local environment has:

- Node.js `v24.14.0`.
- npm available through `npm.cmd` version `11.9.0`.
- Corepack available.
- `pnpm` not currently installed.
- PowerShell script execution blocks `npm.ps1`, so commands should use `npm.cmd` on Windows.

## Stack Decision

Use npm workspaces for the initial monorepo.

Reasons:

- npm is already available locally, while `pnpm` is not installed.
- npm workspaces provide built-in linking for local packages, matching the modular monorepo need without adding a package-manager bootstrap step.
- This keeps Milestone 1 focused on project structure, validation scripts, and safety boundaries.

Use TypeScript across apps and packages.

Reasons:

- The repo requires type-safe code where the stack supports it.
- Shared recommendation, risk, evidence, provider, and paper-trading contracts need compile-time consistency.

Use Fastify for `apps/api`.

Reasons:

- Fastify has first-class TypeScript documentation and a lightweight HTTP surface.
- It is less framework-heavy than NestJS and fits a custom, auditable backend.
- It can expose health and later research endpoints without creating broker or order-placement surface area.

Use Vite React for `apps/web`.

Reasons:

- Vite supports React TypeScript templates and keeps the operator UI separate from backend workflows.
- React aligns with the existing UI research direction: TradingView Lightweight Charts, TanStack Table, shadcn/Radix-style primitives, and Recharts later.

Use Vitest for tests and TypeScript build mode for type checking.

Reasons:

- Vitest is designed around Vite and TypeScript workflows.
- The first scaffold needs fast tests for domain contracts, environment validation, and safety guards.

## Initial Domain Contracts

`packages/core` should define the first stable enums and interfaces:

- `OpportunityDecision`: `watchlist`, `paper_trade`, `avoid`, `needs_more_data`.
- `StrategyFamily`: earnings, momentum, mean reversion, volatility, options, news/sentiment, value/quality, sector/macro, portfolio risk.
- `EvidenceStatus`: research only, watchlist eligible, paper trade eligible, avoid, needs more data.
- Recommendation fields required by `AGENTS.md`: thesis, citations, source timestamps, data freshness, risk/confidence/liquidity scores, downside, invalidation, bull/bear cases, why the system might be wrong, and final decision.

Options-specific fields should support max loss, expiration, strike logic, spread/liquidity risk, event risk, and theta risk, but options recommendations remain blocked from `paper_trade` eligibility unless future historical chain evidence exists.

## API Scaffold

The API should expose only safe utility endpoints at first:

- `GET /health`: returns service status, version, environment, and timestamp.
- No recommendation generation endpoint yet.
- No broker endpoint.
- No order endpoint.
- No live trading route.

Environment validation must:

- Accept development/test/production app modes.
- Require no live broker credentials.
- Reject `LIVE_TRADING_ENABLED=true`.
- Keep provider API keys optional until provider adapters are implemented.

## Web Scaffold

The first UI screen should be an operator console shell, not a landing page.

It should show:

- Current phase/status from static copy until API-backed status exists.
- Safety posture: research first, paper trading first, live trading prohibited.
- Empty-state panels for daily opportunities, strategy evidence, data freshness, and paper-trading review.

No investment recommendations should be generated by the UI scaffold.

## Validation Commands

Root scripts should include:

- `npm.cmd run typecheck`
- `npm.cmd run test`
- `npm.cmd run lint`
- `npm.cmd run format:check`
- `npm.cmd run build`

The first implementation should make these scripts pass locally before any Milestone 1 completion claim.

## Deferred Decisions

- Database migration tool remains deferred to Milestone 2.
- UI component library remains deferred until the operator screens need reusable primitives.
- TradingView Lightweight Charts, TanStack Table, Recharts, and provider SDKs remain deferred until specific screens or adapters require them.
- Broker paper integration remains deferred and must not add order-placement capability in MVP.
- Crypto research remains future phase only.

## Self-Review

- Scope is limited to Milestone 1 scaffold and does not include provider adapters, database schema, scoring, recommendation generation, paper trading, or backtesting implementation.
- No live trading, broker order placement, margin, naked options selling, crypto execution, or guaranteed-return language is introduced.
- The stack decision uses locally available npm tooling rather than adding a package-manager bootstrap dependency.
